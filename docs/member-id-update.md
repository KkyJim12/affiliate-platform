# Member ID update / การเปลี่ยนมาใช้ ID สมาชิก

Updated / อัปเดต: 28 October 2026 / 28 ตุลาคม 2026 (Asia/Bangkok).

The application now identifies members by their existing numeric **Member ID**. Thai UI labels use **เลเวล (Level)**. Existing account UUIDs, numeric IDs, passwords, wallet links, sponsor relationships and payment history are preserved.

ระบบและหน้าจอใช้ **ID สมาชิกตัวเลขเดิม** เป็นตัวระบุสมาชิก และใช้คำว่า **เลเวล (Level)** บัญชี UUID, ID ตัวเลข รหัสผ่าน กระเป๋า สายผู้แนะนำ และประวัติการจ่ายเงินเดิมยังคงอยู่

| Area / ส่วนงาน | Current behavior / การทำงานปัจจุบัน |
| --- | --- |
| Password registration / สมัครด้วยรหัสผ่าน | Send `{password,sponsorCode?}`; the server assigns `memberId`. No name or ID is chosen at registration. / ส่งรหัสผ่านกับรหัสแนะนำถ้ามี ระบบสร้าง ID ให้อัตโนมัติ |
| Member/admin credential login / Login แบบข้อมูลบัญชี | Send `{memberId,password}`, with `memberId` as a positive numeric string. Existing wallet sign-in remains available for external members. / ใช้ ID ตัวเลขกับรหัสผ่าน สมาชิกภายนอกยังลงนามกระเป๋าได้ |
| Identity / ตัวตน | Account responses include internal `id` and public numeric `memberId`, without a username field. Public tree nodes contain `{id,path,parentId}`, with numeric public IDs. / API ไม่ส่งชื่อผู้ใช้และผังสาธารณะมีเฉพาะ ID กับโครงสร้าง |
| Settings / ตั้งค่า | IDs are read-only. `PATCH /api/auth/profile` returns 409; admin user changes accept `{status}` only. / แก้ ID ไม่ได้ ผู้ดูแลเปลี่ยนได้เฉพาะสถานะ |
| Search / ค้นหา | Admin account/payment search uses numeric member IDs. Network lookup accepts `memberId`; internal `root` UUID branch navigation retains authorization checks. / ค้นหาด้วย ID และยังตรวจสิทธิ์สาขาเครือข่าย |
| Legacy transfers / โอนเครดิตเดิม | `recipient` is the active recipient's numeric Member ID. Historical descriptions are rendered with IDs without rewriting the original ledger. / ระบุ ID ผู้รับ และแสดงรายการเดิมด้วย ID โดยไม่เขียนทับ ledger |
| Admin setup / สร้างผู้ดูแล | `npm run admin:create` asks for a password and prints the assigned ID. Noninteractive setup needs `LOOP_ADMIN_PASSWORD`. / ตั้งรหัสผ่านแล้วระบบแจ้ง ID ที่สร้าง |
| Existing administrators / ผู้ดูแลเดิม | `npm run admin:list` lists existing admin IDs/statuses without passwords or public names. It uses the configured PostgreSQL connection. / ดู ID ผู้ดูแลเดิมผ่านฐานข้อมูลที่ตั้งค่าไว้ |

The database retains its legacy private `users.username` storage for compatibility with existing records/imports. It is no longer a selectable identity, login credential, editable profile field or public API response. New private handles are generated by the server. Removing that column is unnecessary for ID-based operation and would discard compatibility data.

ฐานข้อมูลเก็บช่องข้อมูลเก่า `users.username` ไว้ภายในเพื่อรองรับข้อมูลและ importer เดิม ไม่ใช้เป็นชื่อแสดง ข้อมูล login ช่องแก้ไข หรือผล API สาธารณะ บัญชีใหม่มีค่าภายในที่ server สร้างให้ การใช้งานด้วย ID ไม่จำเป็นต้องลบคอลัมน์เดิม

No database reset or contract replacement is required. Registration/funding controls, session protections, wallet signature approvals, fifteen-level prices and payout percentages retain their existing behavior. Clients using earlier request/response names must adopt the fields above.

ไม่ต้อง reset ฐานข้อมูลหรือเปลี่ยน Smart Contract สวิตช์ระบบ การป้องกัน session การลงนามกระเป๋า ราคา 15 เลเวล (Level) และเปอร์เซ็นต์จ่ายเงินทำงานตามกติกาเดิม Client ที่ส่ง field เดิมต้องปรับตามตารางด้านบน
