# การจ่ายเงินไบนารีแมทริกซ์และยูนิเลเวล เวอร์ชัน 3

[English](../matrix-payments.md) · [สารบัญเอกสาร](../README.md) · [คู่มือ Deploy Contract](deploy-contracts.md)

เลเวล (Level) 1 ราคา 10 โทเคน เลเวลถัดไปเพิ่มเป็นสองเท่าจนถึงเลเวล 15 สมาชิกซื้อเลเวลถัดไปเองได้ หรือใช้การอัปเกรดอัตโนมัติหลังเติมช่องแมทริกซ์หรือยูนิเลเวลที่ชำระครบ โดยหักราคาเต็มจากกระเป๋าของสมาชิก สคริปต์ deploy ที่ให้มาใช้โทเคนทดสอบบน Polygon Amoy

## 1. ผังและช่องสมาชิก

ระบบมีผังจัดวางสองแบบ รหัสผู้เชิญใน `users.sponsor_id` ยังคงเป็นคนเดิม แม้สมาชิกที่เชิญเพิ่มจะถูกจัดวางต่อใต้สมาชิกคนอื่น เรียกการลงต่อในช่องว่างว่า **spillover**

- **ไบนารีแมทริกซ์:** ช่องละ 2 สาขา มีลูกด้านล่าง 3 ขั้น เป็น 2 / 4 / 8 ตำแหน่ง รวมเจ้าของเป็น 4 แถว แต่ละเลเวลมีช่องของตนเอง การเชิญเพิ่มจะค้นหาช่องของผู้เชิญตามลำดับรอบ จากแถวบนลงล่าง ซ้ายไปขวา เมื่อไม่มีที่ว่างใน 3 ขั้นจะเปิดช่องใหม่ในเลเวลเดิม เริ่มเป็นรอบใหม่
- **ยูนิเลเวล:** สมาชิกละ 2 สาขา จัดวางต่อเนื่องจากบนลงล่างซ้ายไปขวา ผังและค่าคอมมิชชันครอบคลุมผู้ปกครองเหนือผู้ซื้อ 15 ขั้น เริ่มจาก parent ตามตำแหน่งของผู้ซื้อ สายนี้ต่อเนื่องข้ามรอบแมทริกซ์ได้

ยูนิเลเวลไบนารีที่เต็มทั้ง 15 ขั้นมีสมาชิกด้านล่าง 65,534 ตำแหน่ง เจ้าของและสมาชิกทุกตำแหน่งต้องซื้อเลเวลเดียวกันครบ จึงจะนับว่าจบรอบของเลเวลนั้น

การสมัครจองตำแหน่งทุกเลเวล แต่ตำแหน่งยังล็อกอยู่จนกว่าเจ้าของจะซื้อเลเวลนั้น ช่องที่ล็อกไม่รับค่าคอมมิชชันของเลเวลนั้น และไม่นับเป็นการเติมแมทริกซ์แบบชำระครบ เลเวลที่ซื้อแล้วคงปลดล็อกต่อไป

ตัวอย่าง ผู้ใช้ 2 อยู่แถวแรกใต้ผู้ใช้ 1 จะเห็นสาขาเดียวกันเมื่อเปิดช่องของตนเอง เมื่อผังของผู้ใช้ 1 ชำระครบ 2/4/8 ตำแหน่ง ผู้ใช้ 2 จะมีสมาชิกที่รับต่อมาในสองแถวแรก 2 + 4 คน และเหลือแถวที่สาม 8 ตำแหน่งให้ผู้ใช้ 2 หรือสมาชิกในสาขาของเขาเติม ผู้ใช้ 1 ที่เชิญเพิ่มจะลงช่องรีเบิร์ธของผู้ใช้ 1 เมื่อช่องของผู้ใช้ 2 ครบ จะเปิดรีเบิร์ธของตนเองและเข้าคิวซื้อเลเวลถัดไปที่ยังไม่มี หลังยืนยันการหักเงินอัปเกรดแล้ว ผู้ใช้ 2 จะแสดงในตำแหน่งที่จองไว้ในแมทริกซ์เลเวลถัดไปของผู้ใช้ 1 ส่วนผู้ที่ยังไม่ซื้อเลเวลนั้นจะเว้นว่างไว้

หน้าแนะนำสมาชิกเริ่มต้นด้วยการ์ดช่องแมทริกซ์ แยกช่องเริ่มต้นและรีเบิร์ธของแต่ละเลเวล แต่ละการ์ดแสดงสถานะยังไม่ปลดล็อก กำลังเติมสมาชิก หรือครบแล้ว พร้อมจำนวนตำแหน่งที่ชำระแล้วและที่จองไว้แยกกัน กดการ์ดเพื่อดูผังของเลเวลและรอบนั้น แล้วกดกลับเพื่อเลือกช่องอื่น กรองตามเลเวลและแบ่งหน้าได้เมื่อมีหลายรีเบิร์ธ ช่องที่ล็อกดูผังจองล่วงหน้าได้โดยไม่ซื้อเลเวล ยูนิเลเวลและรายชื่อสมาชิกยังเลือกดูแยกได้ในหน้าเดียวกัน

`GET /api/referrals/slots?level=1&page=1` ส่งความคืบหน้าเฉพาะเจ้าของ session ที่เข้าสู่ระบบ หน้าละไม่เกิน 24 การ์ด ไม่รับ ID ของสมาชิกอื่น ส่วนหน้าผังสาธารณะยังเลือกแผน เลเวล และรอบแมทริกซ์ได้ API สำหรับแมทริกซ์คือ `GET /api/referrals/tree?id=<numeric ID>&mode=matrix&level=1&cycle=0` ส่วนยูนิเลเวลใช้ `mode=unilevel&levels=15` เส้นทางสาขาใช้เฉพาะ `0` กับ `1` คั่นด้วย `/` API สาธารณะส่งเฉพาะ ID ตัวเลขและตำแหน่ง ไม่ส่ง UUID ภายใน กระเป๋า ยอดเงิน หรือสิทธิ์รับเงิน

ผังเลเวล 1 แสดงสมาชิกที่สมัครแล้วทุกคนตามสาขาที่จัดวาง รวมทั้ง spillover และสมาชิกจากสาขาด้านล่าง ส่วนเลเวล 2 ขึ้นไปจะแสดงเมื่อสมาชิกซื้อเลเวลที่เลือกแล้วเท่านั้น ผู้ที่ยังไม่อัปเกรดจะเว้นตำแหน่งว่างไว้ จำนวนในผังเลเวล 1 จึงนับผู้สมัคร ส่วนเลเวลสูงกว่านับผู้ที่ปลดล็อกแล้ว การเปิดใช้งานแบบชำระเงินและสถานะครบแบบชำระครบยังนับแยกต่างหาก การสมัครครบตำแหน่งเพียงอย่างเดียวยังไม่ทำให้อัปเกรดโดยหักเงิน

เจ้าของยังแสดงที่จุดเริ่มต้นของผัง และระบบยังค้นหาสมาชิกผ่าน parent ที่ยังว่างในเลเวลสูงกว่าได้โดยไม่ย้ายตำแหน่ง ผังที่เปิดอยู่รีเฟรชทุก 15 วินาทีขณะแท็บแสดงอยู่ เมื่อกดการ์ดที่ครบแล้วจะแสดงสมาชิกทั้ง 14 ตำแหน่งของเลเวลและรอบนั้น แม้จะมีรีเบิร์ธใหม่แล้ว ช่องเดิมยังคงผังเดิม ส่วนช่องใหม่มีผังแยกต่างหาก

## 2. การแบ่งจ่ายจากการซื้อ

แต่ละรายการแบ่งราคาเต็มเป็น 19 ส่วน:

| แผน | ผู้รับ | ส่วนแบ่ง |
| --- | --- | ---: |
| แมทริกซ์ | ช่อง parent เหนือผู้ซื้อ 1 ขั้น | 10% |
| แมทริกซ์ | เหนือผู้ซื้อ 2 ขั้น | 20% |
| แมทริกซ์ | เหนือผู้ซื้อ 3 ขั้น | 50% |
| ยูนิเลเวล | ผู้ปกครองตามตำแหน่ง 15 ขั้น เริ่มจาก parent | ขั้นละ 1% |
| แพลตฟอร์ม | ที่อยู่ผู้รับค่าธรรมเนียมที่ตั้งค่าไว้ | 5% |

ผู้รับต้องซื้อเลเวลเดียวกับรายการซื้อแล้ว มีบัญชี active และมีกระเป๋าตามโหมดที่ใช้ ส่วนแบ่งของตำแหน่งที่ไม่มีผู้รับหรือยังล็อกจะไปแพลตฟอร์ม ไม่รวมส่วนที่เหลือไปให้ผู้แนะนำคนอื่น Server บันทึกสิทธิ์ ณ เวลาออก quote

ผู้รับของสองผังอาจต่างกัน ลายเซ็นจึงผูกผู้รับ 18 ตำแหน่ง คือแมทริกซ์ 3 และยูนิเลเวล 15 กระเป๋าเดียวรับได้ทั้งสองแผน แต่ห้ามที่อยู่ซ้ำภายในแผนเดียว ห้ามผู้ซื้อรับส่วนแนะนำของตนเอง และห้ามส่งส่วนแนะนำไปยังตัว distributor

ตัวอย่างซื้อ 10 โทเคน หากมีสิทธิ์เฉพาะ parent คนเดียวในทั้งสองผัง parent รับ 1.10 โทเคน คือแมทริกซ์ 1.00 และยูนิเลเวล 0.10 แพลตฟอร์มรับ 8.90 หากทุกตำแหน่งมีสิทธิ์ สมาชิกทั้งหมดรับรวม 9.50 และแพลตฟอร์มรับ 0.50

## 3. ครบรอบและอัปเกรดอัตโนมัติ

เมื่อเจ้าของและสมาชิกด้านล่างทั้ง 14 ช่องปลดล็อกเลเวลนั้นแล้ว ระบบบันทึกการครบรอบครั้งเดียว และเปิดช่องเลเวลเดิมที่ยังมีที่ว่าง เรียกว่า **รีเบิร์ธ (rebirth)** ช่องใหม่มี 2 สาขาและลึก 3 ขั้นเหมือนเดิม โดยเก็บช่องก่อนหน้าไว้ แต่ละช่องรีเบิร์ธเติมสมาชิกจนเต็มและเริ่มรีเบิร์ธต่อได้

แต่ละช่องที่ชำระครบจะเข้าคิวซื้อ **เลเวลถัดไปที่สมาชิกยังไม่มี** สูงสุดเลเวล 15 เช่น ช่องแรกของเลเวล 1 เต็มแล้วซื้อเลเวล 2 เมื่อรีเบิร์ธของเลเวล 1 เต็มอีกครั้งจะซื้อเลเวล 3 หากหลายช่องเต็มพร้อมกันจะจองเลเวลต่อเนื่องกันคนละเลเวล หากสมาชิกซื้อเลเวลที่จองเองก่อน งานนั้นจะเป็น `superseded` โดยไม่หักซ้ำ

ยูนิเลเวลจบรอบได้ครั้งเดียวต่อเลเวล เมื่อเจ้าของและสมาชิกด้านล่างทั้ง 65,534 ตำแหน่งใน 15 ขั้นซื้อเลเวลเดียวกันครบ จะเข้าคิวอัปเกรดแบบเดียวกัน แต่ไม่สร้างช่องรีเบิร์ธหรือย้ายตำแหน่งสมาชิก ทั้งสองแผนหยุดซื้อที่เลเวล 15 โดยแมทริกซ์ยังเปิดรีเบิร์ธต่อได้ และไม่มีเลเวล 16

ราคาอัปเกรดคือ **ราคาเต็มของเลเวลถัดไป** หักจากกระเป๋าสมาชิก ไม่กันค่าคอมมิชชันสะสมไว้ เมื่อยืนยันการซื้อแล้วจะปลดล็อกช่องเลเวลใหม่ และแบ่งจ่ายราคาซื้อด้วยกติกาเดียวกัน

ใน contract mode หน้ายืนยันเสนออนุมัติวงเงินโทเคนแบบจำกัดสำหรับเลเวลปัจจุบันและเลเวลที่เหลือ ที่เลเวล 1 วงเงินสูงสุดคือ 327,670 โทเคน นี่คือเพดาน **allowance** ไม่ใช่ยอดหักทันที หากไม่เลือกตัวเลือกนี้จะอนุมัติเฉพาะราคาซื้อ สมาชิกยกเลิก allowance ที่กระเป๋าได้ หากยอดเงินหรือวงเงินไม่พอ อัปเกรดจะรอในคิว เมื่อเติมเงินแล้วสามารถลองใหม่ด้วยวงเงินที่อนุมัติไว้ โดยไม่ใช้ private key ของสมาชิกใน connected-wallet mode

Quote authority ลงนามรับรองรอบที่ครบด้วย hash `matrixCycle` ฟังก์ชัน `autoUpgrade` รับธุรกรรมจาก relayer ตรวจ quote ลำดับเลเวล และใช้ hash รอบได้ครั้งเดียว หากโอนล้มเหลวจะย้อนการเปลี่ยนสถานะและการแบ่งจ่ายทั้งหมด รวมการใช้ hash รอบด้วย Authority ยังเป็นผู้ที่ระบบเชื่อถือด้านการจัดวาง สิทธิ์ซื้อเดิม สิทธิ์ผู้รับ และรอบที่ครบ ข้อเท็จจริงเหล่านี้อยู่ใน PostgreSQL ไม่ได้เก็บผังทั้งหมดบนเชน

ชื่อฟิลด์ `matrixCycle` ยังคงใช้กับสัญญาเวอร์ชัน 3 โดยแมทริกซ์ใช้ hash ของ ID ช่อง ส่วนยูนิเลเวลใช้ hash ของ `unilevel:<เลเวลที่ครบ>:<UUID สมาชิก>`

Worker ทำงานทุก 15 วินาที บันทึกธุรกรรมที่ลงนามก่อน broadcast และจัดลำดับ nonce ของ relayer ระหว่าง server หลายเครื่อง ต้องเติม **test POL ให้ public address ที่อ่านจาก `quoteSigner()`** เพื่อจ่าย gas การอัปเกรด สมาชิกจ่ายราคาโทเคนตามวงเงิน ส่วน relayer จ่าย gas ธุรกรรมที่ค้างทำต่อได้หลัง restart ด้วย signed bytes เดิม บัญชีที่ระงับไม่เริ่มอัปเกรดใหม่ แต่การระงับนอกเชนไม่ยกเลิกธุรกรรมที่ส่งขึ้นเชนไปแล้ว

ใน embedded ledger mode ระบบหักเครดิต available และบันทึก ledger allocations แทน Platform payable ในโหมดนี้เป็นบัญชีค้างจ่าย ไม่ใช่การโอนโทเคนบนเชน

## 4. ระบบเดิมและการ Deploy

Migration `0013_matrix_slots_and_auto_upgrades.sql` เพิ่มช่องแมทริกซ์และคิวถาวร จัดวางข้อมูลเดิมตามลำดับสมัคร และรักษา paid levels กับ sponsor เดิม ประวัติการจ่ายไม่ถูกแบ่งใหม่ แมทริกซ์เก่าที่เต็มอยู่แล้วไม่ทำให้หักเงินอัปเกรดย้อนหลัง รายการที่ยืนยันในเวอร์ชัน 1–2 ยังคงใช้กติกาบัญชีของเวอร์ชันเดิม

Migration `0014_unilevel_completion_and_rebirth.sql` ย้ายงานเดิมเข้าคิวร่วม `referral_auto_upgrades` เพิ่มความคืบหน้ายูนิเลเวลแบบสะสม และบันทึกผังยูนิเลเวลเดิมที่เต็มแล้วโดยไม่หักเงินย้อนหลัง ชื่อ `matrix_auto_upgrades` ยังคงเป็น view เฉพาะงานแมทริกซ์ การซื้อหนึ่งครั้งอัปเดตผู้ปกครองไม่เกิน 15 คน แทนการอ่านสมาชิกทั้ง 65,534 คน การอัปเดตนี้ใช้ ABI เวอร์ชัน 3 เดิม หาก distributor ปัจจุบันเป็นเวอร์ชัน 3 อยู่แล้ว **ไม่ต้อง deploy สัญญาใหม่** ให้ migrate, build และ restart แอป

สำหรับระบบที่ใช้สัญญาเวอร์ชัน 3 อยู่แล้ว:

```powershell
npm.cmd run db:migrate
npm.cmd run build
```

จากนั้น restart แอปด้วย environment เดิม การเริ่มแอปจะทำ migration ที่ค้างอยู่ให้อัตโนมัติด้วย คำสั่งเปลี่ยน distributor ด้านล่างใช้เฉพาะสัญญาเวอร์ชันเก่า ไม่จำเป็นสำหรับการอัปเดตรีเบิร์ธและยูนิเลเวลครั้งนี้

Distributor ไม่เปลี่ยน code ที่ address เดิมเมื่อแก้ Solidity ต้องรอธุรกรรมค้างให้เสร็จแล้ว deploy ตัวใหม่โดยใช้ token เดิม ตรวจแผนก่อนด้วย:

```powershell
npm.cmd run contracts:deploy -- --replace-distributor
```

แทน `CURRENT_DISTRIBUTOR_ADDRESS` ด้วยที่อยู่ปัจจุบันจริง แล้วจึงส่ง:

```text
npm.cmd run contracts:deploy -- --replace-distributor --previous-contract CURRENT_DISTRIBUTOR_ADDRESS --broadcast
```

สคริปต์บันทึก address ใหม่ลง `.env` จากนั้นทำ migration ยืนยันซอร์ส build และ restart แอปตาม [คู่มือ Deploy ภาษาไทย](deploy-contracts.md) การซื้อใหม่ต้องใช้เวอร์ชัน 3 วงเงินอนุมัติผูกกับ address ของ distributor สมาชิกจึงต้องอนุมัติตัวใหม่ก่อนใช้งาน Owner สามารถ pause ตัวเก่าหลังรายการค้างเสร็จ

การตรวจแบบอ่านอย่างเดียววันที่ 28 ตุลาคม 2026 พบว่า distributor ที่ตั้งค่าไว้รายงานเวอร์ชัน 2 และ quote ล่าสุด 5 รายการเป็นผู้รับศูนย์ทั้งหมด จึงส่งทุกส่วนไปแพลตฟอร์มตามกติกา เวอร์ชัน 3 สร้างผู้รับจากสองผัง หากไม่มีใครเหนือผู้ซื้อปลดล็อกเลเวลที่ซื้อ การจ่ายทั้งหมดไปแพลตฟอร์มยังเป็นผลที่ถูกกำหนดไว้เช่นกัน ข้อมูลนี้เป็นผลตรวจในวันดังกล่าว ไม่ใช่การรับรองสถานะปัจจุบัน

การทดสอบครอบคลุมยอดรวมราคา โทเคน 6/18 decimals ผังแยก สิทธิ์ที่ล็อก spillover 3 ขั้น เปิดรอบใหม่ ครบรอบซ้ำ ผูก sponsor ภายหลัง การหักเงิน และการป้องกัน replay การทดสอบนี้ไม่ใช่การตรวจสอบสัญญาโดยผู้ตรวจอิสระ
