# การจ่ายเงินไบนารีแมทริกซ์และยูนิเลเวล เวอร์ชัน 3

[English](../matrix-payments.md) · [สารบัญเอกสาร](../README.md) · [คู่มือ Deploy Contract](deploy-contracts.md)

เลเวล (Level) 1 ราคา 10 โทเคน เลเวลถัดไปเพิ่มเป็นสองเท่าจนถึงเลเวล 15 สมาชิกซื้อเลเวลถัดไปเองได้ หรือใช้การอัปเกรดอัตโนมัติหลังเติมช่องแมทริกซ์หรือยูนิเลเวลที่ชำระครบ โดยหักราคาเต็มจากกระเป๋าของสมาชิก สคริปต์ deploy ที่ให้มาใช้โทเคนทดสอบบน Polygon Amoy

## 1. ผังและช่องสมาชิก

ระบบมีผังจัดวางสองแบบ รหัสผู้เชิญใน `users.sponsor_id` ยังคงเป็นคนเดิม แม้สมาชิกที่เชิญเพิ่มจะถูกจัดวางต่อใต้สมาชิกคนอื่น เรียกการลงต่อในช่องว่างว่า **spillover**

หน้าค้นหา ID ที่ `/search?id=<ID สมาชิก>` แสดงการ์ดช่องของสมาชิกที่ค้นหาเหมือนหน้าแนะนำสมาชิก กรองตามเลเวล แบ่งหน้า และเลือกรีเบิร์ธได้ กดการ์ดเพื่อดูผังของเลเวลและรอบนั้น หรือเลือกแท็บยูนิเลเวล มุมมองสาธารณะดูข้อมูลได้อย่างเดียว ใช้ `GET /api/referrals/public-slots?id=<ID สมาชิก>&level=1&page=1` ซึ่งส่งเฉพาะ ID ตัวเลขและความคืบหน้าของช่อง ไม่ส่ง UUID ภายใน กระเป๋า ยอดเงิน หรือประวัติการชำระเงิน ส่วน `/api/referrals/slots` ยังคงอ้างอิงเจ้าของ session ที่เข้าสู่ระบบเท่านั้น

- **ไบนารีแมทริกซ์:** ช่องละ 2 สาขา มีลูกด้านล่าง 3 ขั้น เป็น 2 / 4 / 8 ตำแหน่ง รวมเจ้าของเป็น 4 แถว แต่ละเลเวลมีช่องของตนเอง การเชิญเพิ่มจะค้นหาช่องของผู้เชิญตามลำดับรอบ จากแถวบนลงล่าง ซ้ายไปขวา เมื่อไม่มีที่ว่างจะจองตำแหน่งในรอบถัดไป แต่จะเปิดรีเบิร์ธเมื่อเจ้าของและสมาชิกทั้ง 14 ตำแหน่งซื้อเลเวลเดียวกันครบแล้วเท่านั้น
- **ยูนิเลเวล:** ช่องละ 2 สาขา แต่ละเลเวลมีผังและรีเบิร์ธแยกกัน จัดจากบนลงล่างซ้ายไปขวา จ่ายให้ผู้ปกครองเหนือผู้ซื้อ 15 ขั้น เริ่มจาก parent ของช่องในเลเวลที่ซื้อ ขั้นละ 1%

ยูนิเลเวลไบนารีที่เต็มทั้ง 15 ขั้นมีสมาชิกด้านล่าง 65,534 ตำแหน่ง เจ้าของและสมาชิกทุกตำแหน่งต้องซื้อเลเวลเดียวกันครบ จึงจะนับว่าจบรอบของเลเวลนั้น

การสมัครแสดงตำแหน่งในเลเวล 1 และสร้างการ์ดเลเวลถัดไปโดยไม่จองตำแหน่ง เมื่อเข้าเลเวล 2–15 ทั้งสองโปรแกรมจะอ้างอิงสายผู้แนะนำเดิมของเลเวล 1 โดยข้ามผู้แนะนำที่ยังไม่ซื้อเลเวลเป้าหมาย แล้วหาตำแหน่งว่างใต้ผู้แนะนำที่ซื้อแล้วและอยู่ใกล้ที่สุด ตามลำดับรอบ จากบนลงล่าง ซ้ายไปขวา ทุกเลเวลอ้างอิงสายผู้แนะนำเดิมเสมอ ไม่ใช้ผังเลเวลก่อนหน้า เช่น 2 เชิญ 18 และ 18 เชิญ 49 หาก 18 ยังไม่ซื้อเลเวล 2 แต่ 2 ซื้อแล้ว เมื่อ 49 ซื้อเลเวล 2 จะเชื่อมใต้ 2 หากไม่มีผู้แนะนำเหนือขึ้นไปที่ซื้อเลเวลนั้น ช่องใหม่จะไม่มี parent รหัสผู้แนะนำและเลเวลที่ซื้อแล้วคงเดิม ผู้แนะนำที่ซื้อเลเวลตามมาภายหลังไม่ย้ายตำแหน่งที่จองไว้แล้ว

การชำระผ่านสัญญาจองตำแหน่งเมื่อเตรียม quote ที่ลงนามไว้ และคงตำแหน่งระหว่างรอยืนยันหรือลองซ้ำเพื่อให้ตรงกับผู้รับใน quote การจองไม่ถือว่าซื้อแล้วหากธุรกรรมล้มเหลวหรือหมดอายุ ส่วน ledger ย้อนการจองเมื่อซื้อไม่สำเร็จ

ตัวอย่าง ผู้ใช้ 2 อยู่แถวแรกใต้ผู้ใช้ 1 ในเลเวล 1 เมื่อขึ้นเลเวล 2 จะรับตำแหน่งว่างถัดไปใต้ผู้ใช้ 1 ในเลเวล 2 หากสมาชิกอื่นเข้าเลเวล 2 ก่อน สมาชิกนั้นได้ตำแหน่งก่อน เมื่อผู้ใช้ 2 รีเบิร์ธ ช่องใหม่จะกลับไปเชื่อมใต้ผู้แนะนำเดิมที่ตำแหน่งว่างถัดไป ส่วนช่องที่ครบแล้วและสมาชิกเดิมคงอยู่

หน้าแนะนำสมาชิกเริ่มต้นด้วยการ์ดช่องแมทริกซ์ แท็บยูนิเลเวลก็แสดงการ์ดช่องของตนเองก่อน แยกช่องเริ่มต้นและรีบอร์นของแต่ละเลเวล แต่ละการ์ดแสดงสถานะและจำนวนตำแหน่ง แมทริกซ์มี 14 ตำแหน่ง ยูนิเลเวลมี 65,534 ตำแหน่ง กดการ์ดเพื่อดูผังของเลเวลและรอบนั้น แล้วกดกลับเพื่อเลือกช่องอื่น กรองตามเลเวลและแบ่งหน้าได้ ช่องที่ล็อกดูสมาชิกที่เชื่อมอยู่แล้วได้โดยไม่ซื้อเลเวล

ที่แดชบอร์ด กดการ์ดสมาชิกแนะนำตรงเพื่อเปิดรายการ ID ที่คุณเชิญโดยตรง ค้นหาและแบ่งหน้าละ 20 คนได้ โดยไม่ขึ้นกับตำแหน่ง spillover มีปุ่มไปยังผังสมาชิกแนะนำตรง ซึ่งเชื่อมตามผู้เชิญจริงและแสดงได้สูงสุด 500 คนใน 15 ขั้น รายการ ID แนะนำตรงยังใช้สมาชิกที่คุณเชิญทั้งหมด แม้ผังจะแสดงไม่ครบ

API รายการช่องทั้ง `/api/referrals/slots` และ `/api/referrals/public-slots` รับ `mode=unilevel` สำหรับช่องยูนิเลเวล ค่าเริ่มต้นคือ `mode=matrix` และแสดงหน้าละไม่เกิน 24 ช่อง

`GET /api/referrals/slots?level=1&page=1` ส่งความคืบหน้าเฉพาะเจ้าของ session หน้าละไม่เกิน 24 การ์ด API ผังสาธารณะเลือกโปรแกรม เลเวล และรอบได้ เช่น `GET /api/referrals/tree?id=<numeric ID>&mode=matrix&level=1&cycle=0` และ `mode=unilevel&level=2&cycle=1&levels=15` เส้นทางสาขาใช้ `0` กับ `1` คั่นด้วย `/` ส่งเฉพาะ ID ตัวเลข ตำแหน่ง และ `purchased` ซึ่งหมายถึงการซื้อเลเวลที่เลือกในทั้งสองโปรแกรม ไม่ส่ง UUID ภายใน กระเป๋า หรือยอดเงิน

เลเวล 1 แสดงสมาชิกทันทีที่สมัคร เลเวลถัดไปแสดงเมื่อเข้าเลเวลนั้น สมาชิกที่ยังไม่ซื้อแต่มีตำแหน่งอยู่แล้วจะแสดงป้าย "ยังไม่ได้ซื้อ" จำนวนในแมทริกซ์นับเฉพาะตำแหน่งที่ชำระแล้ว การสมัครเพียงอย่างเดียวไม่เปิดรีเบิร์ธหรือหักเงินอัปเกรด รอบที่จองล่วงหน้าจะไม่แสดงจนกว่ารอบก่อนหน้าจะชำระครบ

เจ้าของยังแสดงที่จุดเริ่มต้นของผัง เลเวล 1 ยังคงแสดงสมาชิกที่ยังไม่ซื้อและเส้นเชื่อมเดิม การเข้าเลเวลสูงกว่า 1 ครั้งใหม่จะข้ามผู้แนะนำที่ยังไม่ซื้อเลเวลนั้น ส่วนสายที่ชำระแล้วหรือมี quote ค้างอยู่ก่อนเปลี่ยนกติกายังคงตำแหน่งเดิม ผังที่เปิดอยู่รีเฟรชทุก 15 วินาทีขณะแท็บแสดงอยู่ เมื่อกดการ์ดที่ครบแล้วจะแสดงสมาชิกทั้ง 14 ตำแหน่งของเลเวลและรอบนั้น แม้จะมีรีบอร์นใหม่แล้ว ช่องเดิมยังคงผังเดิม ส่วนช่องใหม่มีผังแยกต่างหาก

## 2. การแบ่งจ่ายจากการซื้อ

แต่ละรายการแบ่งราคาเต็มเป็น 19 ส่วน:

| แผน | ผู้รับ | ส่วนแบ่ง |
| --- | --- | ---: |
| แมทริกซ์ | ช่อง parent เหนือผู้ซื้อ 1 ขั้น | 10% |
| แมทริกซ์ | เหนือผู้ซื้อ 2 ขั้น | 20% |
| แมทริกซ์ | เหนือผู้ซื้อ 3 ขั้น | 50% |
| ยูนิเลเวล | ผู้ปกครองตามตำแหน่ง 15 ขั้น เริ่มจาก parent | ขั้นละ 1% |
| แพลตฟอร์ม | ที่อยู่ผู้รับค่าธรรมเนียมที่ตั้งค่าไว้ | 5% |

ผู้รับต้องซื้อเลเวลเดียวกับรายการซื้อแล้ว มีบัญชี active และมีกระเป๋าตามโหมดที่ใช้ ส่วนแบ่งของตำแหน่งที่ไม่มีผู้รับหรือยังล็อกจะไปแพลตฟอร์ม ไม่รวมส่วนที่เหลือไปให้ผู้แนะนำคนอื่น Server บันทึกสิทธิ์ ณ เวลาออก quote

ผู้รับของสองผังอาจต่างกัน ลายเซ็นจึงผูกผู้รับ 18 ตำแหน่ง คือแมทริกซ์ 3 และยูนิเลเวล 15 กระเป๋าเดียวรับได้ทั้งสองแผน แต่ห้ามที่อยู่ซ้ำภายในแผนเดียว ห้ามผู้ซื้อรับส่วนแนะนำของตนเอง และห้ามส่งส่วนแนะนำไปยังตัว distributor

ตัวอย่างซื้อ 10 โทเคน หากมีสิทธิ์เฉพาะ parent คนเดียวในทั้งสองผัง parent รับ 1.10 โทเคน คือแมทริกซ์ 1.00 และยูนิเลเวล 0.10 แพลตฟอร์มรับ 8.90 หากทุกตำแหน่งมีสิทธิ์ สมาชิกทั้งหมดรับรวม 9.50 และแพลตฟอร์มรับ 0.50

## เงื่อนไขสมาชิกแนะนำตรงที่ชำระแล้ว 2 คน

Distributor เวอร์ชัน 4 กำหนดให้มีสมาชิกที่แนะนำโดยตรงและชำระค่าเปิดใช้งานสำเร็จอย่างน้อย 2 คนก่อนรับค่าคอมมิชชัน ใช้เงื่อนไขเดียวกันทั้ง 15 เลเวล แมทริกซ์ ยูนิเลเวล การอัปเกรด และรีเบิร์ธ ไม่ต้องเริ่มนับใหม่ในแต่ละรอบ การสมัครอย่างเดียว ตำแหน่งล้น รายการที่ยังไม่ยืนยันหรือล้มเหลว และการซื้อซ้ำของคนเดิมไม่นับเพิ่ม โดยดูผู้แนะนำจาก `users.sponsor_id`

ค่าคอมมิชชันของสมาชิกที่ยังไม่ครบเงื่อนไขจะพักใน `heldCommissions` ภายในสัญญา ไม่ส่งให้แพลตฟอร์มและยังใช้ซื้อเลเวลหรือรีเบิร์ธไม่ได้ เมื่อสมาชิกแนะนำตรงคนที่สองชำระสำเร็จ สัญญาจะจ่ายยอดที่พักไว้ทั้งหมดอัตโนมัติ และจ่ายรายการใหม่ตามปกติ ค่าธรรมเนียมแพลตฟอร์มและสิทธิ์ผู้รับตามเลเวลยังใช้กติกาเดิม ยอดที่พักไว้ไม่มีวันหมดอายุตามเงื่อนไขนี้

Quote authority ลงนามรับรองผู้แนะนำและข้อมูลสมาชิกที่ชำระแล้วในฐานข้อมูล รวมบัญชีเดิม หากบัญชีที่ชำระแล้วเพิ่งเชื่อมผู้แนะนำ Worker จะส่ง `qualifyCommission` เพื่อจ่ายยอดที่พักไว้ โดยบันทึกธุรกรรมก่อนส่งเพื่อทำต่อหลัง restart และไม่จ่ายซ้ำ ใน ledger mode จะพัก allocations และเครดิตเมื่อครบเงื่อนไข หน้าสมาชิกแสดงจำนวนผู้แนะนำที่ชำระและยอดที่พักไว้ ส่วนรายได้ที่จ่ายแล้วไม่รวมยอดพัก

ให้ใช้ migration `0019_commission_qualification.sql`, build และ restart แอป พร้อม deploy distributor **เวอร์ชัน 4** สัญญาเวอร์ชัน 3 เดิมไม่รองรับเงื่อนไขนี้ ต้องยืนยันรายการเดิมที่ค้างก่อนเปลี่ยนที่อยู่สัญญาและอนุมัติโทเคนให้สัญญาใหม่ รายได้เดิมที่จ่ายแล้วไม่ถูกเรียกคืน

## 3. ครบรอบและอัปเกรดอัตโนมัติ

เมื่อเจ้าของและสมาชิกด้านล่างทั้ง 14 ช่องซื้อเลเวลนั้นแล้ว ระบบบันทึกการครบรอบครั้งเดียว และเปิดรอบถัดไปในเลเวลเดิม เรียกว่า **รีเบิร์ธ (rebirth)** ช่องใหม่มี 2 สาขาและลึก 3 ขั้นเหมือนเดิม โดยเก็บช่องก่อนหน้าไว้ รอบที่จองไว้และชำระครบแล้วจะตรวจตามลำดับ แต่ละรอบต้องครบเงื่อนไขเดียวกันก่อนเปิดรีเบิร์ธถัดไป

แต่ละช่องที่ชำระครบจะเข้าคิวซื้อ **เลเวลถัดไปที่สมาชิกยังไม่มี** สูงสุดเลเวล 15 เช่น ช่องแรกของเลเวล 1 เต็มแล้วซื้อเลเวล 2 เมื่อรีเบิร์ธของเลเวล 1 เต็มอีกครั้งจะซื้อเลเวล 3 หากหลายช่องเต็มพร้อมกันจะจองเลเวลต่อเนื่องกันคนละเลเวล หากสมาชิกซื้อเลเวลที่จองเองก่อน งานนั้นจะเป็น `superseded` โดยไม่หักซ้ำ

ยูนิเลเวลจบรอบเมื่อเจ้าของและสมาชิกด้านล่างทั้ง 65,534 ตำแหน่งใน 15 ขั้นซื้อเลเวลเดียวกันครบ จะเข้าคิวอัปเกรดและเปิดรีเบิร์ธเลเวลเดิมที่เชื่อมใต้ผู้แนะนำเดิม ช่องเดิมคงสมาชิกเดิมไว้ ทั้งสองโปรแกรมหยุดซื้อที่เลเวล 15 แต่ยังเปิดรีเบิร์ธต่อได้ ไม่มีเลเวล 16

รีเบิร์ธแต่ละครั้งหักราคาเต็มของเลเวลเดิมจากยอดคงเหลือแยกต่างหาก: เลเวล 1 = 10 โทเคน เลเวล 2 = 20 เลเวล 3 = 40 และเพิ่มเป็นสองเท่าจนถึงเลเวล 15 รายการนี้จ่ายตามผู้ปกครองของตำแหน่งรีเบิร์ธใหม่ อีกโปรแกรมใช้ช่องล่าสุดที่เปิดและชำระแล้วในเลเวลเดียวกัน แบ่งเป็นแมทริกซ์ 10% / 20% / 50% ยูนิเลเวล 1% จำนวน 15 ขั้น และแพลตฟอร์ม 5% ช่องรีเบิร์ธและรอบที่จองล่วงหน้ายังไม่มีสิทธิ์รับค่าคอมมิชชันหรือจบรอบจนกว่าจะชำระสำเร็จ

อัปเกรดจะรอให้ชำระค่ารีเบิร์ธก่อน ราคาอัปเกรดคือ **ราคาเต็มของเลเวลถัดไป** หักจากกระเป๋าสมาชิกแยกจากค่ารีเบิร์ธ ไม่กันค่าคอมมิชชันสะสมไว้ เมื่อยืนยันการซื้อแล้วจะปลดล็อกช่องเลเวลใหม่ และแบ่งจ่ายราคาซื้อด้วยกติกาเดียวกัน ค่ารีเบิร์ธและอัปเกรดใช้ allowance เดียวกัน จึงอาจต้องอนุมัติวงเงินเพิ่มเมื่อรีเบิร์ธหลายครั้ง

ใน contract mode หน้ายืนยันเสนออนุมัติวงเงินโทเคนแบบจำกัดสำหรับเลเวลปัจจุบันและเลเวลที่เหลือ ที่เลเวล 1 วงเงินสูงสุดคือ 327,670 โทเคน นี่คือเพดาน **allowance** ไม่ใช่ยอดหักทันที หากไม่เลือกตัวเลือกนี้จะอนุมัติเฉพาะราคาซื้อ สมาชิกยกเลิก allowance ที่กระเป๋าได้ หากยอดเงินหรือวงเงินไม่พอ อัปเกรดจะรอในคิว เมื่อเติมเงินแล้วสามารถลองใหม่ด้วยวงเงินที่อนุมัติไว้ โดยไม่ใช้ private key ของสมาชิกใน connected-wallet mode

Quote authority ลงนามรับรองรอบที่ครบด้วย hash `matrixCycle` ฟังก์ชัน `autoUpgrade` รับธุรกรรมจาก relayer ตรวจ quote ลำดับเลเวล และใช้ hash รอบได้ครั้งเดียว หากโอนล้มเหลวจะย้อนการเปลี่ยนสถานะและการแบ่งจ่ายทั้งหมด รวมการใช้ hash รอบด้วย Authority ยังเป็นผู้ที่ระบบเชื่อถือด้านการจัดวาง สิทธิ์ซื้อเดิม สิทธิ์ผู้รับ และรอบที่ครบ ข้อเท็จจริงเหล่านี้อยู่ใน PostgreSQL ไม่ได้เก็บผังทั้งหมดบนเชน

ชื่อฟิลด์ `matrixCycle` ยังคงใช้กับสัญญาเวอร์ชัน 3 โดยแมทริกซ์ใช้ hash ของ ID ช่อง ยูนิเลเวลรอบแรกใช้ hash ของ `unilevel:<เลเวลที่ครบ>:<UUID สมาชิก>` และรอบรีเบิร์ธใช้ ID ช่องที่มีหมายเลขรอบรวมอยู่ด้วย

Worker ทำงานทุก 15 วินาที บันทึกธุรกรรมที่ลงนามก่อน broadcast และจัดลำดับ nonce ของ relayer ระหว่าง server หลายเครื่อง ต้องเติม **test POL ให้ public address ที่อ่านจาก `quoteSigner()`** เพื่อจ่าย gas การอัปเกรด สมาชิกจ่ายราคาโทเคนตามวงเงิน ส่วน relayer จ่าย gas ธุรกรรมที่ค้างทำต่อได้หลัง restart ด้วย signed bytes เดิม บัญชีที่ระงับไม่เริ่มอัปเกรดใหม่ แต่การระงับนอกเชนไม่ยกเลิกธุรกรรมที่ส่งขึ้นเชนไปแล้ว

ใน embedded ledger mode ระบบหักเครดิต available และบันทึก ledger allocations แทน Platform payable ในโหมดนี้เป็นบัญชีค้างจ่าย ไม่ใช่การโอนโทเคนบนเชน

## 4. ระบบเดิมและการ Deploy

Migration `0013_matrix_slots_and_auto_upgrades.sql` เพิ่มช่องแมทริกซ์และคิวถาวร จัดวางข้อมูลเดิมตามลำดับสมัคร และรักษา paid levels กับ sponsor เดิม ประวัติการจ่ายไม่ถูกแบ่งใหม่ แมทริกซ์เก่าที่เต็มอยู่แล้วไม่ทำให้หักเงินอัปเกรดย้อนหลัง รายการที่ยืนยันในเวอร์ชัน 1–2 ยังคงใช้กติกาบัญชีของเวอร์ชันเดิม

Migration `0014_unilevel_completion_and_rebirth.sql` ย้ายงานเดิมเข้าคิวร่วม `referral_auto_upgrades` เพิ่มความคืบหน้ายูนิเลเวลแบบสะสม และบันทึกผังยูนิเลเวลเดิมที่เต็มแล้วโดยไม่หักเงินย้อนหลัง ชื่อ `matrix_auto_upgrades` ยังคงเป็น view เฉพาะงานอัปเกรดแมทริกซ์ การซื้อหนึ่งครั้งอัปเดตผู้ปกครองไม่เกิน 15 คน แทนการอ่านสมาชิกทั้ง 65,534 คน Migration 0014 เองใช้ ABI เวอร์ชัน 3 เดิม แต่ระบบเก็บค่ารีเบิร์ธใน 0018 ต้องใช้สัญญาที่มีฟังก์ชันเพิ่ม

Migration `0015_paid_matrix_rebirths.sql` แยกรอบที่จองล่วงหน้าจากรีเบิร์ธที่เปิดแล้ว โดยเก็บตำแหน่ง รอบที่ครบแล้ว และหลักฐานการชำระเงินเดิมไว้ รอบถัดไปที่ยังไม่ผ่านเงื่อนไขจะไม่แสดงในการ์ดและตัวเลือกรอบ

Migration `0016_dynamic_program_placement.sql` ยกเลิกการจองเลเวลถัดไปที่ยังไม่ซื้อ เพิ่มช่องยูนิเลเวลแยกตามเลเวล และเชื่อมรีเบิร์ธใต้ผู้แนะนำเดิม โดยรักษาสายที่ชำระแล้ว ตำแหน่งของ quote ที่ยังรอยืนยัน ประวัติการแบ่งจ่าย และงานอัปเกรด ช่องยูนิเลเวลเดิมที่เต็มจะได้รับรอบใหม่โดยไม่หักเงินย้อนหลัง ใช้ ABI เวอร์ชัน 3 และเปอร์เซ็นต์เดิม ไม่ต้อง deploy distributor ใหม่

Migration `0020_skip_unpaid_level_inviters.sql` เปลี่ยนการเข้าเลเวล 2–15 ครั้งใหม่ให้ข้ามผู้แนะนำเดิมที่ยังไม่ซื้อเลเวลเป้าหมาย รวมถึงช่องรีบอร์น โดยรักษาตำแหน่งที่จองแล้ว สายที่ชำระแล้ว และผู้รับของ quote ที่ยังค้างอยู่ รวม quote ที่ไม่มี parent ไม่แบ่งจ่ายประวัติใหม่และไม่ต้องเปลี่ยนสัญญา

Migration `0018_rebirth_payments.sql` เก็บค่ารีเบิร์ธเฉพาะรอบที่ครบใหม่ รักษารีเบิร์ธที่เปิดแล้วและงานอัปเกรดเดิมโดยไม่หักย้อนหลัง ต้องใช้ distributor ใหม่ที่มี `rebirthVersion() = 1` และฟังก์ชัน `rebirth` สัญญาเวอร์ชัน 3 เดิมที่ไม่มีฟังก์ชันนี้จะรอในคิวพร้อมข้อความให้ deploy สัญญาที่รองรับ ค่ารีเบิร์ธจ่ายครั้งเดียวต่อรอบและไม่เปลี่ยนเลเวลสูงสุดที่สมาชิกมี

สำหรับระบบที่ใช้สัญญาเวอร์ชัน 3 อยู่แล้ว ให้ migrate และ build พร้อมเปลี่ยน distributor หากยังไม่มี `rebirthVersion() = 1`:

```powershell
npm.cmd run db:migrate
npm.cmd run build
```

จากนั้น restart แอปด้วย environment เดิม การเริ่มแอปจะทำ migration ที่ค้างอยู่ให้อัตโนมัติด้วย คำสั่งเปลี่ยน distributor ด้านล่างใช้เฉพาะสัญญาเวอร์ชันเก่า ไม่จำเป็นสำหรับการอัปเดตรีเบิร์ธและยูนิเลเวลครั้งนี้

Distributor ไม่เปลี่ยน code ที่ address เดิมเมื่อแก้ Solidity ต้องรอธุรกรรมค้างให้เสร็จแล้ว deploy ตัวใหม่โดยใช้ token เดิม ตรวจแผนก่อนด้วย:

```powershell
npm.cmd run contracts:deploy -- --replace-distributor
```

แทน `CURRENT_DISTRIBUTOR_ADDRESS` ด้วยที่อยู่ปัจจุบันจริง แล้วจึงส่ง:

```text
npm.cmd run contracts:deploy -- --replace-distributor --previous-contract CURRENT_DISTRIBUTOR_ADDRESS --broadcast
```

สคริปต์บันทึก address ใหม่ลง `.env` จากนั้นทำ migration ยืนยันซอร์ส build และ restart แอปตาม [คู่มือ Deploy ภาษาไทย](deploy-contracts.md) การซื้อใหม่ต้องใช้เวอร์ชัน 3 วงเงินอนุมัติผูกกับ address ของ distributor สมาชิกจึงต้องอนุมัติตัวใหม่ก่อนใช้งาน Owner สามารถ pause ตัวเก่าหลังรายการค้างเสร็จ

การตรวจแบบอ่านอย่างเดียววันที่ 28 ตุลาคม 2026 พบว่า distributor ที่ตั้งค่าไว้รายงานเวอร์ชัน 2 และ quote ล่าสุด 5 รายการเป็นผู้รับศูนย์ทั้งหมด จึงส่งทุกส่วนไปแพลตฟอร์มตามกติกา เวอร์ชัน 3 สร้างผู้รับจากสองผัง หากไม่มีใครเหนือผู้ซื้อปลดล็อกเลเวลที่ซื้อ การจ่ายทั้งหมดไปแพลตฟอร์มยังเป็นผลที่ถูกกำหนดไว้เช่นกัน ข้อมูลนี้เป็นผลตรวจในวันดังกล่าว ไม่ใช่การรับรองสถานะปัจจุบัน

การทดสอบครอบคลุมยอดรวมราคา โทเคน 6/18 decimals ผังแยก สิทธิ์ที่ล็อก spillover 3 ขั้น เปิดรอบใหม่ ครบรอบซ้ำ ผูก sponsor ภายหลัง การหักเงิน และการป้องกัน replay การทดสอบนี้ไม่ใช่การตรวจสอบสัญญาโดยผู้ตรวจอิสระ
